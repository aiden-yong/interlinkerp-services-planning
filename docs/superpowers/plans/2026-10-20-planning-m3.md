# Planning M3 (Repeating Shifts, Templates, Copying, Splitting) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Managers can repeat a shift, plan from templates, copy last week and split a shift, and repeated shifts keep being generated up to the horizon.

**Architecture:** A pure generator turns a stored series (`recurrences`) into dated occurrences. A `RecurrenceService` writes them inside the existing `UnitOfWork`, under a per-series advisory lock, with `on conflict do nothing` on a unique `(organisation_id, recurrence_id, recurrence_index)` index that also covers soft-deleted rows. Templates, week copies and splits are small services beside `ShiftService`. The client extends the existing shift dialog and schedule toolbar.

**Tech Stack:** As before: Next.js 16, React 19, TypeScript strict, Drizzle ORM 0.45 on PostgreSQL 18, Luxon, Vitest 5, Playwright. No new dependencies.

**Spec:** [docs/superpowers/specs/2026-10-20-planning-m3-design.md](../specs/2026-10-20-planning-m3-design.md) (decisions D1–D13) and [ListOfRequirements.md](../../../ListOfRequirements.md).

## Global Constraints

- **Naming:** the ERP is **InterlinkERP**. Its former brand name never appears anywhere.
- **Commits:** conventional types, no attribution lines. Work on `feature/m3-recurrence-templates` off `main` in the main checkout. The user's dev server on port 3000 and `.env.local` are never touched. Browser tests use port 3200.
- **Layering:** `src/server/**` never imports React or `src/client/**`; `src/client/**` never imports `src/server/**`. Every query filters `organisation_id`.
- **API contract:** error envelope `{"error":{"code","message","correlation_id","details"}}`; POST 201, GET and PATCH 200, DELETE 204 (series deletes return 200 with `{ deleted }`); instants ISO UTC; every new code is added to `ERROR_CODES` in `src/server/http/errors.ts`; every new non-public route gets an `op(...)` doc and appears in a `catalog.ts` capability (`openapi.test.ts` enforces both).
- **Version:** `SERVICE_VERSION` becomes `0.3.0` in Task 1 and is not bumped again within M3.
- **Migration:** exactly one new migration, `0004`, generated in Task 1 with `npm run db:generate -- --name recurrence_templates`. It must not change after Task 1 is reviewed. Add every new table to `TABLES` in `src/server/test/db.ts`.
- **Wall clock:** every date arithmetic that moves a shift by days, weeks or months uses Luxon in a named zone (the series' `timezone`, or the organisation's for copies), never fixed milliseconds.
- **Writes go through `UnitOfWork`;** a transaction never awaits the pool (use the `scope` repositories).
- **Limits (from the spec):** `interval` 1..99; `occurrence_count` 1..999; `recurrence_horizon_months` 1..24, default 6; at most 1,000 shifts per series per generation run; template name ≤ 80 characters; template `duration_minutes` 1..10,080; split leaves ≥ 15 minutes on each side.

## Review Focus

1. **A weekly 09:00 series in a zone with daylight saving** keeps starting at 09:00 local after the clock change [Task 2 test `keeps 09:00 across a DST change`].
2. **The organisation changes its time zone after a series exists:** later occurrences keep the series' own zone, so they do not jump [Task 3 test `extends in the series' own zone`].
3. **"All" edit while some occurrences are published, detached or already started:** only untouched not-started drafts change [Task 4 test `leaves published, detached and started shifts alone`].
4. **The cron and a schedule read extend the same series at the same moment:** no duplicate shifts [Task 3 test `two extensions at once create each shift once`].
5. **Copy previous week across a month end or a DST change:** copies land at the same weekday and wall-clock time [Task 7 test `copies across a month end at the same wall-clock time`].

### Task 2: The occurrence generator (pure)

**Files:**
- Create: `src/server/domain/recurrence.ts`, `src/server/domain/recurrence.test.ts`

**Interfaces:**
- Produces:
```ts
export type RepeatUnit = 'day' | 'week' | 'month';
export type RepeatEnds = 'never' | 'on' | 'after';
export interface RepeatRule {
  interval: number; unit: RepeatUnit; ends: RepeatEnds;
  untilDate: string | null;   // YYYY-MM-DD, inclusive, for 'on'
  count: number | null;       // for 'after': number of created shifts, step 0 included
  timezone: string;           // IANA
  firstStartLocal: string;    // 'YYYY-MM-DDTHH:MM' wall clock of step 0
  durationMinutes: number;    // end - start, wall-clock independent
  lastIndex: number | null;   // a series ended early stops after this step
}
export interface Occurrence { index: number; start: Date; end: Date }
export const MAX_PER_RUN = 1000;
/** Steps with index >= fromIndex whose start is < until, in order, at most MAX_PER_RUN. */
export function occurrences(rule: RepeatRule, fromIndex: number, until: Date): Occurrence[];
```
- Algorithm (not determined by the signature): step `k` starts at `DateTime.fromISO(firstStartLocal, { zone }).plus({ [unit + 's']: k * interval })`. For `month`, a step whose `day` differs from step 0's `day` is skipped (D2) but still consumes its index. `end = start + durationMinutes` in real time. `count` counts **non-skipped** steps from index 0, so walk from 0 when `ends === 'after'` and only emit those `>= fromIndex`. Stop at `lastIndex`, at `untilDate` (compare the step's local date), at `until`, or after `MAX_PER_RUN` emitted.

```ts
// repo/recurrences.ts
export interface SeriesRecord extends RepeatRule {
  id: string; employeeRef: string | null; roleId: string | null; breakMinutes: number; percent: number; note: string | null;
  generatedUntil: Date; createdBy: string;
}
export class RecurrenceRepository {
  find(id: string): Promise<SeriesRecord | null>;
  insert(s: SeriesRecord, now: Date): Promise<void>;
  update(s: SeriesRecord, now: Date): Promise<void>;
  dueForExtension(before: Date): Promise<string[]>; // ids with generated_until < before and not ended
}
export function seriesToApi(s: SeriesRecord, index: number | null, detached: boolean):
  { id: string; interval: number; unit: RepeatUnit; ends: RepeatEnds; until_date: string | null; count: number | null; index: number | null; detached: boolean };
// scheduling/recurrenceService.ts
export class RecurrenceService {
  /** Validates `repeat`; returns the rule fields or adds field errors to input. */
  parseRepeat(input: Input, key: 'repeat'): Pick<RepeatRule, 'interval' | 'unit' | 'ends' | 'untilDate' | 'count'> | null;
  /** In the caller's transaction: insert the series from `first`, insert first + occurrences up to now + horizon. */
  createSeries(scope: WriteScope, first: ShiftRecord, repeat: ..., zone: string, horizonMonths: number, ack: { by: string; at: Date } | null, now: Date): Promise<{ seriesId: string; created: number }>;
  /** Conflicts of every occurrence that createSeries would make, for the SHIFT_CONFLICT answer (D8). */
  previewConflicts(first: ShiftRecord, repeat: ..., zone: string, horizonMonths: number, now: Date): Promise<{ date: string; conflicts: Conflict[] }[]>;
  /** Generate missing shifts for one series up to now + horizon; one transaction, lockSeries first. */
  extendOne(id: string, now: Date): Promise<number>;
  /** All series due; never throws, logs failures; returns shifts created. */
  extendAll(now: Date): Promise<number>;
}
```
- Behaviour (spec D1, D3, D4, D8):
  - `POST /api/shifts` with `repeat` stores the series with `timezone` = organisation zone, `firstStartLocal`/`durationMinutes` from the first shift, and gives the first shift `recurrenceIndex: 0`. Conflicts: if any occurrence (first included) conflicts and `acknowledge_conflicts` is not true, 409 `SHIFT_CONFLICT` with `details: { conflicts, occurrences: [{ date, conflicts }] }`; when acknowledged, each conflicting shift records the manager.
  - Response: `201 { shift, conflicts, recurrence: { id, created } }`, `created` counting the first shift.
  - `extendOne` loads the series, generates from `max(existing index)+1` (by `select max(recurrence_index)` including deleted rows) up to `now + horizon months` (Luxon `plus({ months })` in the series zone), inserts with `insertMany`, sets `generated_until`. Generated shifts copy the series attributes, are drafts, and carry no acknowledgement.
  - The notifications cron calls `app.recurrences().extendAll(now)` before delivery and adds `extended` to its JSON. `ScheduleService.build` calls `extendAll(now)` first only when `dueForExtension(now + horizon − 1 day)` is non-empty.
  - Every shift payload gets `recurrence: seriesToApi(...) | null` and `copied_from`. Load series for a list of shifts in one query.

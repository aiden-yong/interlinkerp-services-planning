# Planning M4 (Reporting, Auto Plan, Audit Trail, Year View, Calendar Feed, Reminders) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Managers get planned-hours, utilisation and open-shift reports with CSV export, an Auto Plan that fills draft open shifts without conflicts, a per-shift history, a Year scale and department grouping; employees get a private calendar feed and reminders before their shifts.

**Architecture:** Reports and Auto Plan are pure functions over the same records the schedule reads (`src/server/reports/*`, `src/server/domain/autoPlan.ts`), wrapped by thin services that load data and, for Auto Plan, write inside the existing `UnitOfWork`. The audit trail is an `AuditRepository` on `WriteScope`, so every write records its entry in the same transaction. Reminders are one more step in the existing notification sweep plus a light cron route an external scheduler calls. The calendar feed is a public route keyed by a hashed secret token.

**Tech Stack:** As before: Next.js 16, React 19, TypeScript strict, Drizzle ORM 0.45 on PostgreSQL 18, Luxon, Vitest 5, Playwright. No new dependencies (the property test uses a small seeded generator written in the test).

**Spec:** [docs/superpowers/specs/2026-10-21-planning-m4-design.md](../specs/2026-10-21-planning-m4-design.md) (decisions D1–D26) and [ListOfRequirements.md](../../../ListOfRequirements.md).

## Global Constraints

- **Naming:** the ERP is **InterlinkERP**. Its former brand name never appears anywhere.
- **Commits:** conventional types, no attribution lines. Work on `feature/m4-reporting-auto-plan` (already created off `main`, holding the spec commit) in the main checkout. The user's dev server on port 3000 and `.env.local` are never touched. Browser tests use port 3200. Never write test rows through the local server: `.env` points at the remote database.
- **Layering:** `src/server/**` never imports React or `src/client/**`; `src/client/**` never imports `src/server/**`. Every query filters `organisation_id`.
- **API contract:** error envelope `{"error":{"code","message","correlation_id","details"}}`; POST 201, GET and PATCH 200, DELETE 204; instants ISO UTC; every new code is added to `ERROR_CODES` in `src/server/http/errors.ts`; every new non-public route gets an `op(...)` doc and appears in a `catalog.ts` capability (`openapi.test.ts` enforces both).
- **Version:** `SERVICE_VERSION` becomes `0.4.0` in Task 1 and is not bumped again within M4.
- **Migration:** exactly one new migration, `0005`, generated in Task 1 with `npm run db:generate -- --name reporting_audit_feeds`, plus the hand-written back-fill (D18) appended to it. It must not change after Task 1 is reviewed. Add every new table to `TABLES` in `src/server/test/db.ts`.
- **Same numbers as the schedule:** reports and Auto Plan compute hours with `allocatedByDay`, `availableByDay`, `overAllocatedDays` and `workingIntervals`, in each employee's own zone, through the helpers Task 2 extracts from `ScheduleService`. No second implementation of BR-04.
- **Writes go through `UnitOfWork`;** a transaction never awaits the pool (read the directory before opening the transaction).
- **Limits (from the spec):** report period ≤ 366 days (`PERIOD_TOO_LONG`, 422); `reminder_lead_minutes` ∈ {0, 30, 60, 120, 240, 720, 1440}, default 60, 0 = off; feed token 32 random bytes (base64url), stored as SHA-256 hex; feed window 30 days back to the recurrence horizon ahead; feed `Cache-Control: private, max-age=900`; sweep alert after 30 minutes without a run.
- **Copy (exact):** Auto Plan reasons are `No one on the roster has this role`, `Everyone with this role is on flexible hours`, `Outside everyone's working hours`, `Everyone with this role is busy or away then`, `Would put everyone over their available hours`, plus `Already published, left for employees to claim` and `Changed while Auto Plan ran`.

## Review Focus

1. **A shift across midnight at the edge of the report period, in an employee zone with a DST change:** only the part inside the period counts, split on that employee's local days [Task 2 test `counts only the part inside the period, on the employee's own days`].
2. **An employee whose profile zone differs from the viewer's:** the planned-hours report for a week equals the schedule's `allocated_hours` for the same week [Task 3 test `matches the schedule for the same week`].
3. **A night shift 22:00–06:00 against working hours Mon 22:00–24:00 and Tue 00:00–06:00:** Auto Plan treats it as inside working hours [Task 4 test `treats back-to-back working ranges across midnight as one`].
4. **Names with commas, quotes, line breaks, non-Latin letters or a leading `=`:** CSV quotes them, keeps UTF-8 with a BOM, and neutralises the formula [Task 2 test `quotes and neutralises awkward cells`].
5. **A shift reassigned after its owner subscribed:** it leaves the old owner's feed and appears in the new owner's; a reset token answers 404 [Task 8 test `follows reassignment and reset`].

### Task 4: Auto Plan planner (pure) with the property test

**Files:**
- Create: `src/server/domain/autoPlan.ts`, `src/server/domain/autoPlan.test.ts`, `src/server/domain/autoPlan.property.test.ts`

**Interfaces:**
- Consumes: `ReportEmployee`, `ReportPeriod`, `allocatedInPeriod`, `availableInPeriod` (Task 2); `conflictsForEmployee`, `subtract`, `workingIntervals`, `ShiftFacts`.
- Produces:
```ts
export interface OpenDraft { id: string; roleId: string | null; start: Date; end: Date; breakMinutes: number; percent: number; version: number }
export interface Candidate extends ReportEmployee { existing: ShiftFacts[] }   // their live shifts overlapping period ± 7 days
export type UnfilledReason = 'no_role_holder' | 'all_flexible' | 'outside_working_hours' | 'busy_or_away' | 'over_available';
export const REASON_TEXT: Record<UnfilledReason, string>;   // the exact copy in Global Constraints
export interface AutoPlanResult { assignments: { shiftId: string; employeeRef: string }[]; unfilled: { shiftId: string; reason: UnfilledReason }[] }
export function planAutoAssignments(open: OpenDraft[], people: Candidate[], period: ReportPeriod): AutoPlanResult;
```
- Algorithm (D9–D12), not determined by the signature:
  1. For a shift, narrow the pool step by step; the first step that empties it gives the reason:
     - S0 `no_role_holder`: on roster, at least one role, and (shift has no role or holds it).
     - S1 `all_flexible`: S0 with `workingHours !== null`.
     - S2 `outside_working_hours`: `subtract(shiftInterval, workingIntervals(hours, start, end, zone))` is empty (so adjacent ranges across midnight count as one, Review Focus 3).
     - S3 `busy_or_away`: no BR-01 conflict for the shift among `existing` + this run's assignments, with `away` (time off and holidays) and `roleIds`.
     - S4 `over_available`: after adding it, `overAllocatedDays` over the shift's local days is empty.
  2. Order shifts by S4 pool size against the starting state (ascending), then `start`, then `id`. Process in that order, recomputing the pool against the running state.
  3. Pick: default role equals shift role first; then fewest allocated hours in the period (`allocatedInPeriod` over existing + assigned); then `name`; then `ref`. Add the shift to the winner's running `existing`.
